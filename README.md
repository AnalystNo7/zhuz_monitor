# Мониторинг качества проектной документации

Инструмент читает журналы учёта замечаний (ЖУЗ) из выбранной папки и считает по каждому
проектному документу интегральный индекс качества документа (ИИКД) по методике оценки
качества документации. По датам замечаний он восстанавливает, как оценка менялась
во времени, и показывает динамику по месяцам или кварталам.

Это один автономный HTML-файл размером около 60 КБ. Он открывается в браузере двойным
щелчком, не требует установки, прав администратора и доступа в интернет. Файлы из папки
никуда не передаются: расчёт выполняется на компьютере пользователя.

Состояние: прототип. Готовы расчётное ядро и минимальный интерфейс; графики, детализация
по замечаниям, настройки и выгрузка в Excel — следующие этапы (см. «План»).

## Как пользоваться

1. Открыть `zhuz-monitor.html` в Chrome, Edge или Яндекс Браузере.
2. Нажать «Открыть папку» и выбрать папку с журналами. Подпапки читаются тоже.
3. Выбрать детализацию (кварталы или месяцы), состояние (текущее или на конец периода)
   и статус документа.
4. В разделе «Ручной ввод» внизу страницы назначить РП проектам, при необходимости задать
   статус и число циклов документов и нажать «Сохранить в папку».

Кнопка «Обновить» перечитывает ту же папку без повторного выбора.

## Что должно лежать в папке

```
Качество ПД/
  Мониторинг ПД - ручной ввод.xlsx  РП, статусы, циклы — создаётся из формы инструмента
  Проект А/
    ЖУЗ_Техническое задание.xlsx    один журнал на документ
    ЖУЗ_Проектное решение.xlsx
    Перечень документов.xlsx        необязательно: расширенный Шаблон_1 этого РП
  Проект Б/
    …
```

Названия и вложенность папок могут быть любыми.

### Журналы

Книги Excel по шаблону ЖУЗ. Действуют два правила:

- **Один документ — один журнал.** Документ определяется связкой «Проект — Документ»
  из самого журнала (по первому замечанию). Новая версия документа с новым наименованием —
  это другой документ со своим журналом.
- **Журнал только пополняется.** Новые замечания дописываются в тот же файл, файл можно
  просто заменять. Если в папке окажется несколько копий одного журнала, актуальной
  считается самая полная, остальные в расчёт не идут. Копией считается журнал, у которого
  не меньше 80 % замечаний есть в более полном.
- **Версии документа.** Документ, который актуализируют по новому заказу или этапу, — отдельная
  версия со своим журналом, даже если наименование то же. Журналы с той же связкой
  «проект — документ», но с другими замечаниями считаются разными версиями.

Отдельных папок под каждую загрузку не нужно: история восстанавливается по датам замечаний.

### Перечень документов

`Шаблон_1`, который заполняет руководитель проекта, с тремя добавленными колонками.
У каждого РП свой перечень. Перечень необязателен: без него число циклов оценивается
по журналу, а РП и статус документа задаются в разделе «Ручной ввод».

| Колонка | Обязательна | Назначение |
|---|---|---|
| Проект, РП, Проектный документ | да | Кому и к чему относится оценка |
| Статус документа | нет | Фильтр по статусу; можно задать вручную |
| Внутреннее согласование, Внешнее согласование | нет | Пока не используются: раздельная оценка экспертиз не решена |
| Отв. за разработку, способ согласования, Ссылка на папку | нет | Как в исходном шаблоне |
| **Количество циклов согласования** | нет | Четвёртый показатель; если пусто — оценивается по журналу |
| **Количество листов** | нет | Нужно только для режима «норматив на 10 листов» |
| **Файл ЖУЗ** | нет | Имя файла журнала либо «Без замечаний» |

Над таблицей указывается дата перечня: `Данные на 30.09.2026`, `Отчетный период: сентябрь 2026`
или `Отчетный период: 3 квартал 2026`.

- **Связь с журналом** — по имени в колонке «Файл ЖУЗ». Если колонка пуста, журнал ищется
  по совпадению проекта и документа.
- **Одноимённые документы проекта** в разных папках («Ссылка на папку») — разные версии.
  В интерфейсе к наименованию добавляется подпись версии: последняя папка из ссылки
  («заказ 4.1»), иначе имя файла журнала, а если и они совпадают — номер. Строки с одинаковыми
  проектом, наименованием и папкой вызывают предупреждение: версию лучше указать в наименовании.
- **Документ, согласованный без замечаний,** вносится со значением «Без замечаний» и получает 100.
- **Несколько перечней за разное время** дают историю статуса и числа циклов: на каждую дату
  берутся сведения из последнего перечня не позже неё.

### Ручной ввод

В разделе «Ручной ввод» задаются:

- **РП** — для проекта целиком, действует для всех его документов;
- **статус документа** — один из трёх: «Согласован», «На согласовании», «На доработке»;
- **число циклов согласования** — если оценка по журналу или значение из перечня неверны.

Введённое вручную важнее перечня и оценки по журналу. Статус и циклы действуют с даты ввода:
на конец прошлых периодов берутся прежние данные, чтобы не переписывать историю задним числом.
Очистить поле — вернуться к значению из перечня или журнала.

Кнопка «Сохранить в папку» записывает файл `Мониторинг ПД - ручной ввод.xlsx` в корень выбранной
папки; браузер один раз спросит разрешение на изменение файлов. В файле два листа:
«РП по проектам» (Проект, РП) и «Документы» (Проект, Документ, Статус, Циклы согласования,
Изменено). Его видят все, кто открывает эту папку, и его можно править в Excel.
Если браузер не умеет записывать в папку, файл скачивается — его нужно положить в папку вручную.

Если файлов ручного ввода несколько, при совпадении проектов и документов действует изменённый позже.

Пример заполненной папки создаёт команда `npm run samples` (данные вымышленные).

## История и динамика

- **Точка отсчёта документа** — дата первого замечания в журнале. Для документа без замечаний —
  дата перечня.
- **Состояние на дату** — замечания, выданные не позже этой даты. Так из одного актуального
  журнала получается оценка на любой прошлый момент.
- **Динамика считается нарастающим итогом:** на конец каждого месяца или квартала учитываются
  все документы, начатые к этому времени. Документ без новых замечаний переходит в следующий
  период с прежней оценкой.
- **История документа** — его состояние на каждую дату, когда журнал пополнялся.
- **«Изменение»** в таблице документов — разница ИИКД с концом предыдущего периода.

Статусы замечаний берутся из актуального журнала: если замечание было «Новое», а позже стало
«Принято», оно считается принятым с даты выдачи.

### Циклы согласования

Число циклов берётся из ручного ввода, затем из перечня, а если его нет и там — оценивается
по журналу:

- если в журнале есть строки-разделители «Цикл согласования 1», «Цикл согласования 2»…
  хотя бы для двух циклов, используются они;
- иначе новый цикл начинается, когда после предыдущего замечания прошло больше 7 дней
  и замечания выданы к новой версии файла (колонка «Наименование файла и версия документа»).
  Если версия не указана, решает только перерыв в датах;
- учитываются замечания с любым статусом: отклонённые тоже означают, что документ рассматривали;
- документ, согласованный без замечаний, прошёл один цикл.

На семи пилотных журналах правило дало то же число циклов, что и в реестре, там, где их можно сравнить.

## Как считается ИИКД

```
ИИКД = Σ Wn × Bn
Bn   = max(0; 100 − Sn × kn)
Sn   = max(0; Xn − N)
```

| Показатель | Вес Wn | Норматив N | Штраф kn |
|---|---|---|---|
| Оформление | 0,15 | 4 замечания | 1 |
| Содержание | 0,35 | 8 замечаний | 5 |
| Повторные замечания | 0,30 | 1 замечание | 10 |
| Циклы согласования | 0,20 | 3 цикла | 15 |

Зоны: 90–100 — зелёная, от 70 до 90 — жёлтая, ниже 70 — красная. ИИКД округляется до сотых,
зона определяется по округлённому значению.

### Принятые решения

- **Норматив плоский** — на документ целиком, без пересчёта на 10 листов. Режим
  `per10pages` реализован и включается настройкой.
- **Учитываются замечания** со статусами «Принято» и «Согласовано с комментарием».
  «Отклонено» и «Новое» в расчёт не идут.
- **Замечание считается один раз.** Если в ячейке несколько категорий, берётся более
  тяжёлый показатель: повтор, затем содержание, затем оформление.
- **Одинаковые по тексту замечания одного журнала объединяются:** методика считает
  уникальные замечания.
- **Если у принятого замечания нет категории** (пусто или нет в справочнике), журнал
  не рассчитывается: показатель был бы искажён. Документ показывается как «не рассчитан»
  с номерами строк, в журнале загрузки — ошибка. Отклонённые и новые замечания без категории
  расчёт не блокируют, но о них выводится предупреждение.
- **Категории и показатели:**

  | Показатель | Категории замечаний |
  |---|---|
  | Оформление | Корректировка оформления и структуры документа; Орфографические и грамматические ошибки |
  | Содержание | Изменение / дополнение содержания; Уточнение / корректировка информации; Ошибки в терминологии; Корректировка с учётом нормативных документов; Уточнение требований к функциональности |
  | Повторы | Учет ранее выданных замечаний |
  | Не учитываются | Организационные и процессные вопросы; Прочее |

- **Документ, для которого журнал не найден**, не рассчитывается и в средние не входит.
- **Внутренняя и внешняя экспертиза пока не разделяются:** все замечания журнала идут
  в одну оценку. Вопрос открыт.

Все константы и справочники собраны в `src/core/config.ts`.

### Как разбирается журнал

- Шапка и колонки ищутся по названиям, а не по позициям: скрытые, лишние и переставленные
  колонки не мешают.
- Строка-подсказка под шапкой, пустые строки и разделители вроде «Цикл согласования 1»
  пропускаются.
- Пустая ячейка «Проект» заполняется значением из предыдущей строки.
- Замечание без даты относится к дате первого замечания журнала.
- Нераспознанные статусы и категории попадают в журнал загрузки с номерами строк.
- Если даты замечаний пять строк подряд и больше растут ровно на день, или версия файла
  отличается только числом, растущим на единицу, в журнале загрузки появляется предупреждение:
  так бывает, когда ячейку протягивают мышью в Excel.

## Разработка

Нужен Node.js 22.18 или новее.

```bash
npm install
```

```bash
npm test
```

```bash
npm run build
```

```bash
npm run samples
```

`npm run build` проверяет типы и собирает `dist/zhuz-monitor.html` — именно этот файл
передаётся пользователям. `npm run dev` запускает страницу в режиме разработки.

### Структура

```
src/core/     расчётное ядро без привязки к браузеру
  config.ts     константы методики и справочники
  journal.ts    разбор листа ЖУЗ, объединение повторов, циклы согласования
  registry.ts   разбор перечня документов
  classify.ts   статус и категория замечания → показатель
  score.ts      формула ИИКД и зоны
  manual.ts     ручной ввод (РП, статусы, циклы): разбор, запись, подстановка
  pipeline.ts   отбор актуальных журналов, связывание с перечнями
  timeline.ts   состояние документа на дату, периоды, история
  aggregate.ts  сводка, рейтинг РП, динамика
src/io/       чтение и запись .xlsx, доступ к папке
src/ui/       интерфейс
tests/        тесты: пример из методики, строки пилотного реестра, разбор файлов, история
scripts/      сборка и генерация демонстрационных данных
```

Книги Excel читает собственный небольшой модуль на библиотеке `fflate`: актуальная версия
SheetJS не публикуется в npm, а доступная там содержит известные уязвимости. Модуль
изолирован в `src/io/xlsx.ts`, заменить его на другую библиотеку можно без правок ядра.
