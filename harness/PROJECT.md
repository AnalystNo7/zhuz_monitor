## 1. Назначение

Мониторинг качества проектной документации по журналам учёта замечаний (ЖУЗ).
Инструмент читает книги Excel из выбранной папки и считает по каждому проектному
документу интегральный индекс качества документа (ИИКД) по методике оценки качества
документации. Показывает сводку, динамику по месяцам и кварталам, таблицу документов,
рейтинг руководителей проектов (РП) и журнал загрузки с ошибками в данных.

- Форма поставки: один автономный HTML-файл (около 90 КБ), открывается в браузере
  двойным щелчком. Без установки, без сервера, без сети: файлы читаются на компьютере
  пользователя.
- Пользователи: руководство, проектный офис и ещё одно подразделение — по письму-постановке.

Зависимости модулей идут в одну сторону: `ui → io, core`; `io/xlsx.ts → core/types`;
внутри `core` — `pipeline → journal, registry, manual`; `timeline → score`;
`aggregate → timeline, score`.

## 4. Поток данных

1. `folder.ts` — пользователь выбирает папку, собираются все `.xlsx/.xlsm` с подпапками
   (кроме временных `~$…`).
2. `load.ts` + `xlsx.ts` — каждая книга читается в `SheetData[]`; нечитаемые попадают
   в журнал загрузки.
3. `pipeline.evaluate()` — каждый лист распознаётся по шапке как одно из:
   ЖУЗ → `journal.ts`; перечень документов → `registry.ts`;
   ручной ввод (лист «Проект — РП» или «Проект — Документ — Статус — Циклы») → `manual.ts`.
   Затем:
   - из копий одного журнала выбирается самая полная;
   - журналы связываются со строками перечней;
   - собираются `ProjectDocument[]` с историей сведений из перечней (`passports`);
   - одноимённым документам проекта даются подписи версий.
4. `manual.applyManual()` — подставляются РП, статусы и циклы из ручного ввода
   (в интерфейсе, поверх результата `evaluate()`).
5. `timeline.stateAt(doc, дата)` — состояние документа на дату: учитываются замечания
   не позже даты, сведения из перечня на эту дату, ручной ввод с даты изменения;
   считается ИИКД (`score.ts`).
6. `aggregate.ts` — сводка, рейтинг РП, динамика по периодам.
7. `App.tsx` выводит результат; форма ручного ввода сохраняет книгу в папку
   (`folder.save`) или отдаёт её на скачивание.

## 5. Предметная область

| Понятие | Где в коде | Суть |
|---|---|---|
| ЖУЗ (журнал учёта замечаний) | `journal.ts`, `Journal` | один журнал на документ, только пополняется |
| Перечень документов | `registry.ts`, `Registry` | расширенный Шаблон_1 от РП; у каждого РП свой; необязателен |
| Ручной ввод | `manual.ts`, `ManualData` | РП проекта, статус и циклы документа; книга `Мониторинг ПД - ручной ввод.xlsx` |
| Документ | `ProjectDocument` | связка «проект — документ»; одноимённые в разных папках — разные версии (`variant`) |
| Состояние на дату | `DocumentState`, `stateAt` | основа истории и динамики |
| ИИКД | `score.ts` | Σ Wn × Bn; Bn = max(0; 100 − Sn × kn) |
| Зоны | `config.zones` | 90+ зелёная, 70+ жёлтая, ниже — красная |
| Циклы согласования | `journal.assignCycles`, `stateAt` | вручную → из перечня → по журналу |
| Не рассчитан | `MissingPart` | нет ЖУЗ или у принятых замечаний нет категории |

Решения с причинами — в `harness/DECISIONS.md`. Подробные правила расчёта — в README, разделы «Как считается ИИКД»,
«Принятые решения», «Циклы согласования», «История и динамика».

## 8. Правила и ограничения

- Реальные журналы, перечни и методику в репозиторий не класть: в них персональные данные
  и внутренняя информация (README, раздел «Данные»; `.gitignore` → `/data/`).
  Тесты и демо — только на вымышленных данных.
- Ядро (`src/core`) не зависит от браузера: всё, что можно, тестируется в Node.
- Поддерживаются только `.xlsx/.xlsm`; старый `.xls` и защищённые паролем книги не читаются.
- Запись в папку работает только в браузерах с File System Access API (Chrome, Edge,
  Яндекс Браузер); в остальных файл ручного ввода скачивается.
- Репозиторий на GitHub публичный (на момент составления карты).
