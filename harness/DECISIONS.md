## 2026-11-12 — Одноимённые документы в разных папках — разные версии
- Решение: документ проекта с тем же наименованием, но в другой папке («Ссылка на папку») — отдельная версия с подписью (последняя папка, имя файла журнала или номер). Журнал — ранняя копия, только если ≥ 80 % его замечаний есть в более полном.
- Почему: документы актуализируют по разным заказам; каждая версия — свой ЖУЗ (ответ заказчика).
- Затронуто: `src/core/pipeline.ts` (`assignVariants`, `COPY_SHARE`), `src/core/manual.ts` (`documentTitle`)

## 2026-11-12 — Ручной ввод РП, статуса и циклов; действует с даты ввода
- Решение: РП (на проект), статус из трёх и число циклов (на документ) задаются в форме и хранятся в папке книгой «Мониторинг ПД - ручной ввод.xlsx». Ручное важнее перечня и оценки по журналу; статус и циклы применяются только с даты ввода.
- Почему: перечни у каждого РП свои и могут отсутствовать; файл в папке видят все; переписывать историю задним числом заказчик пока не хочет.
- Затронуто: `src/core/manual.ts`, `src/ui/ManualForm.tsx`, `src/io/folder.ts`, `src/core/timeline.ts`

## 2026-11-12 — Число циклов оценивается по журналу
- Решение: циклы берутся из ручного ввода, затем из перечня, иначе по журналу: строки «Цикл согласования N» (если их ≥ 2), иначе новый цикл — перерыв > 7 дней и новая версия файла.
- Почему: перечень может отсутствовать; на пилотных журналах правило дало те же числа, что и реестр.
- Затронуто: `src/core/journal.ts` (`assignCycles`), `src/core/timeline.ts`, `config.cycleGapDays`

## 2026-11-12 — Принятое замечание без категории блокирует расчёт журнала
- Решение: если у принятого замечания категория пуста или не из справочника, документ «не рассчитан» с номерами строк; непринятые без категории — только предупреждение.
- Почему: без категории замечание нельзя отнести к показателю, и ИИКД был бы искажён (решение заказчика).
- Затронуто: `src/core/journal.ts`, `src/core/timeline.ts`, `src/ui/App.tsx`

## 2026-11-12 — Внутренняя и внешняя экспертиза пока не разделяются
- Решение: все замечания журнала идут в одну оценку; колонки согласования в перечне читаются, но не используются.
- Почему: у заказчика вопрос не решён; раздельная оценка требует понять, как экспертизы различаются в журнале.
- Затронуто: `src/core/registry.ts`, `src/core/pipeline.ts`

## 2026-11-12 — Один ЖУЗ на документ, история — по датам замечаний
- Решение: документ — связка «проект — документ» из журнала; журнал только пополняется; состояние на любую дату восстанавливается по датам замечаний; из копий журнала берётся самая полная. Динамика — нарастающим итогом, детализация месяц или квартал.
- Почему: так ведутся журналы (ответ заказчика); не нужны отдельные папки и снимки на каждую загрузку.
- Затронуто: `src/core/pipeline.ts`, `src/core/timeline.ts`, `src/core/aggregate.ts`

## 2026-11-12 — Правила подсчёта замечаний
- Решение: учитываются статусы «Принято» и «Согласовано с комментарием», «Новое» — нет; замечание с несколькими категориями — один раз по более тяжёлому показателю (повтор > содержание > оформление); «Организационные» и «Прочее» не учитываются; одинаковые по тексту замечания журнала — одно.
- Почему: решения заказчика; методика считает уникальные замечания.
- Затронуто: `src/core/config.ts`, `src/core/classify.ts`, `src/core/journal.ts`

## 2026-11-12 — Норматив плоский, а не на 10 листов
- Решение: нормативы оформления и содержания (4 и 8) — на документ целиком; режим `per10pages` оставлен настройкой.
- Почему: так считает пилотный реестр (решение заказчика); число листов документа нигде не указано.
- Затронуто: `src/core/config.ts` (`normMode`), `src/core/score.ts`

## 2026-11-12 — Чтение xlsx своим модулем на fflate вместо SheetJS
- Решение: книги читаются и пишутся собственным модулем поверх zip-библиотеки `fflate`.
- Почему: актуальная SheetJS не публикуется в npm, а версия в npm содержит известные уязвимости; заодно HTML весит ~90 КБ вместо 1–2 МБ. Чтение сверено с openpyxl на шести реальных книгах: 1282 ячейки без расхождений.
- Затронуто: `src/io/xlsx.ts`, `src/io/xlsx-write.ts`

## 2026-11-12 — Форма поставки: один автономный HTML-файл
- Решение: приложение собирается в один HTML, открывается двойным щелчком, без сервера и сети.
- Почему: нужно пересылать по почте и запускать без установки и прав администратора; exe режут почтовые шлюзы и антивирусы; книга с Power Query плохо разбирает неоднородные журналы.
- Затронуто: `vite.config.ts`, `scripts/postbuild.mjs`
